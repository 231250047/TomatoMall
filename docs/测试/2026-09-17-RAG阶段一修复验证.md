## 2. 关键断言

| 场景 | 检查内容 |
| --- | --- |
| 合法空 items | 返回没有足够匹配，不包含检索候选、不调用商品详情回填 |
| 合法非空选品 | 展示真实商品及价格、引用 |
| 非候选 ID、虚构引用 | 明确推荐不可用，不展示未核验候选或模型编造内容 |
| 空正文、非法 JSON、缺少 items | 与业务无匹配分开处理 |
| 模型调用异常 | 不展示候选，不泄漏异常正文 |
| 商品在模型调用后下架 | 最终不推荐该商品 |
| 检索为空 | 不调用模型 |
| 供应商空正文与 length | 抛受控原因，记录结束原因和用量 |
| 非空但截断 | 不当作成功响应 |
| HTTP 401、读取超时、供应商 JSON 非法 | 分别记录 HTTP_ERROR、TIMEOUT、INVALID_RESPONSE |
| 日志安全 | 不出现测试密钥、完整提示词、回答、推理内容或供应商错误正文 |

### 空正文的诊断结论

本轮 9 次模型调用均有正文且 finishReason=stop，没有重现历史空正文。q35 的 completionTokens=1937、reasoningTokens=1875，接近当前 2000 输出额度；q01 reasoningTokens=1283。说明思考输出占用较多额度，但不能证明上轮空正文就是截断，也不能据一次成功称空正文问题已根治。

诊断能力已补齐：下次可直接区分 EMPTY_CONTENT、length、超时与 HTTP 错误。当前未盲目提高额度或关闭思考；需要捕获实际失败并做单独参数对照。
