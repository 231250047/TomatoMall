# 支付通知隧道配置

## 当前状态

用户已要求暂缓公网隧道配置。个人热点尝试后仍无法正常联网，不再继续重试；公司网络限制是用户的推测，尚未确认。商城运行不依赖此隧道。

本地受限转发器已准备并启动。用户已明确同意 Cloudflare 转发沙箱支付通知；重新启动隧道时因本机无法解析 api.trycloudflare.com 失败，独立 curl 检查也返回 Could not resolve host。后端 notify_url 尚未修改，当前不能接收公网通知。未改动系统 DNS 或网络设置。

## 方案

支付宝 → Cloudflare 临时 HTTPS 域名 → 本机 127.0.0.1:18090 → 127.0.0.1:8080/api/orders/notify。

仅允许 POST /api/orders/notify，拒绝查询参数和其他路径；仅接收表单，正文最大 64 KiB。转发器不修改原始正文，不转发 Cookie 或 token，不记录通知正文和签名。商城仍验证支付宝签名、应用、商户、金额和订单状态。

Cloudflare 会处理经过隧道的支付通知，其中可能包含订单号、交易号、金额、买家标识及签名。隧道不需要应用私钥。临时域名可能随重启改变，仅用于沙箱联调。

## 网络恢复后的步骤

1. 建立到 18090 的 Cloudflare Quick Tunnel。
2. 从公网验证其他接口不可访问，无效签名通知返回 fail。
3. 更新受限本地配置中的 notify_url，重启后端。
4. 新建订单，检查支付表单使用新地址，由用户完成沙箱支付。
5. 检查真实通知到达、订单 SUCCESS 和库存只扣一次；同步记录实际结果。

已有订单不能假定自动改用新通知地址，验收使用新订单。
