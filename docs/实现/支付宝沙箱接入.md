# 支付宝沙箱接入记录（2026-09-16）

## 当前配置

用户登录支付宝开放平台后，确认默认网页／移动沙箱应用已启用系统默认密钥、公钥模式，并支持电脑网站支付。此次使用已有系统默认密钥，没有更改平台密钥。

已将 App ID、商户 PID、Java 格式应用私钥、支付宝公钥及沙箱网关接入本地运行配置：

- 主配置：项目 `tmp/local-demo/application.properties`。
- 同步副本：`/private/tmp/tomatomall-demo/application.properties`。
- 两份文件均为权限 600；主配置经 `git check-ignore` 确认被忽略。本文不记录私钥、买家密码或支付表单签名。
- 网关：`https://openapi-sandbox.dl.alipaydev.com/gateway.do`。
- 浏览器返回地址：`http://localhost:8080/api/orders/returnUrl`。

后端已从项目内的主配置重新启动。数据库、Redis、MQ 的数据目录目前仍在临时目录，尚未完成整体环境持久化整理。

## 已实际验证

1. 使用本地 `demo` 账号创建演示订单 3，金额 45.00 元。
2. 调用支付接口成功生成 RSA2 签名表单；之前占位私钥导致的签名异常不再出现。
3. 在保有登录态的商城浏览器标签页进入支付页，自动提交表单。
4. 实际跳转到 `https://excashier-sandbox.dl.alipaydev.com/standard/auth.htm`，收银台显示 45.00 元、沙箱收款方及付款倒计时。

初次本地结构断言错误地假设签名一定是隐藏 input；检查 SDK 表单发现签名位于 action 查询参数中。浏览器最终到达沙箱收银台，是本次跳转验收依据。

新建独立标签页可能没有商城 sessionStorage 中的登录态，应先登录，或在已登录标签页通过“我的订单 → 支付”操作。

## 后续进展与未完成项

- 支付宝收银台已显示“该笔订单已完成付款”（用户完成操作）；本地支付状态和库存的最终验收仍需单独核对。
- 支付成功后的本地订单状态、库存扣减与重复通知验证。
- 公网异步通知：当前 `notify-url` 仍是 localhost，支付宝服务器无法访问，因此支付完成后不能期待异步通知立即更新订单。
- 公网回调可通过受控隧道仅转发 `/api/orders/notify`，或使用用户已有测试服务器。开放公网入口需要先明确暴露范围与授权，再部署。

浏览器 returnUrl 只做导航，不更新支付状态。现有到期处理会主动查询渠道，但它不能替代“支付后立即确认”的异步通知验收。不要用手动修改订单状态冒充真实回调验证。

## 用户下一步

在开放平台的“沙箱账号”页获取买家账号和支付密码，在明确标注沙箱域名的收银台操作。不要使用真实支付宝账户密码替代沙箱测试密码。

当前收银台可能随订单到期失效；到期后应创建新订单重新验证。
