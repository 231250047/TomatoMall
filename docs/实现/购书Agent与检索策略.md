# 购书 Agent 与检索策略

2026-09-17 实现：[规划](../计划/购书场景-RAG精确查询与Agent职责重规划.md)中的单轮购书路由和候选范围修正。是受限只读编排，不包含多轮记忆、自动反复检索、加购或支付。实际验证见[测试报告](../测试/2026-09-17-购书Agent验证.md)。

## 用户输入如何执行

以“Java入门书，50块以下”为例：

1. `BookPurchaseFilter.fromText` 从原话确定价格≤50，推荐默认要求在售且有可售库存。复杂或未支持金额表达请求澄清，不由模型随意填价格。
2. `BookToolPlanner` 通过 DeepSeek 原生 `tools/tool_calls` 选择 `search_books`，参数为 `semanticQuery=Java入门书`。
3. 后端只接受该工具白名单字段，不接收模型的价格覆盖、level、topK或权重参数。调用固定hybrid策略，10个选品候选，沿用既有RRF和两路候选保留规则。
4. MySQL筛出满足购买条件的ID；pgvector在这些ID中先过滤后取topK；关键词路使用同一合格集合。
5. `GroundedBookRecommendation` 调用既有模型选品，传入原始用户问题、候选文本及实时价格库存；检查商品ID与原文证据，返回前重新读取商品事实。

此处工具JSON只描述要检索的语义或明确对象；价格参数由后端基于原话构造。第一版故意采用保守的规则预算解析，以便模型不能更改硬边界；尚不支持任意口语金额及组合预算。

## 三种固定策略

| 场景 | 策略 | 模型调用 |
| --- | --- | --- |
| Java入门、绘画学习、文学体验等 | search_books → 固定混合检索 → 有依据选品 | 通常1次工具选择+1次选品 |
| 明确《书名》或ISBN | 直接lookup_books，展示当前价格与库存、最多5个版本 | 0次，且0次Embedding |
| 明确作者著作、无书名号的对象查询 | 模型选择lookup_books，按规格中的作者/ISBN或书名精确查询 | 1次工具选择，结果由后端格式化 |
| 只有明确价格条件 | search_books空semanticQuery → 数据库列表按价格升序 | 1次工具选择，0次Embedding |
| 闲聊问候、模糊/合计预算 | 直接回应或澄清 | 已覆盖短句与预算规则0次调用 |

用户说“类似某书”“作者风格”时走语义需求；“不要《某书》”跳过直接书名快捷路由，保留原需求交模型筛选。复杂否定仍属于语义能力，不能声称任意表达都已正确识别。

## 谁决定权重

模型只从3个工具中选择：search_books、lookup_books、clarify。它不能传SQL、排序权重、候选数量或新筛选字段。`ProductRetrievalService`保留后端固定RRF规则与阈值；价格库存通过确定性条件保证，不与相关性分数竞争。

`BookToolPlanner`使用已有DeepSeek配置和HTTP适配方式，保持deepseek-v4-flash；路由temperature=0，max_tokens=700，thinking disabled，连接5秒/读取15秒。使用官方原生tool_calls接口，校验恰好一个调用以及工具名、JSON对象、字段与类型；未使用beta strict模式。

模型只选一次工具，后端执行后：字段查询直接格式化事实，语义检索交既有选品调用处理。它不是自由ReAct循环，不自动把工具结果回填后继续让模型调用更多工具；因此没有虚构的“已完成多轮自主Agent”。现有Spring AI M4继续负责向量，不为本次路由强行升级整个依赖栈。

## 购买条件与作者的具体边界

- 以下/以内/不超过含边界；低于/不到严格排除边界，按0.01元处理。上下限取交集，冲突报错。
- 预算50、预算￥50、明确比较后的无单位金额支持；中文金额、左右预算、多书合计等要求澄清。
- 标准书名号内文本不当价格解析；出版年份、ISBN、页数不能直接当预算。
- 精确作者从商品规格“作者”读取，支持分号或顿号分隔的多作者；书中介绍某作者不等于该作者著作。ISBN从同名规格读取。没有新增完整作者实体库；缺失数据不会伪造精确命中。
- 字段查询可以报告缺货/下架商品，而购买推荐只返回在售且有货；明确“只要有货/有货的/现货”仍会过滤。
- 非书名号输入等复杂意图依赖模型路由。未知字段或不在原问题中的明确书名/作者参数拒绝执行。

## 向量候选修正

`ProductVectorIndex`新增 `search(query, limit, eligibleIds)`，旧方法保留。`PgProductVectorIndex`用项目M4已有`Filter.Expression(IN)`对productId过滤；空ID集不调用Embedding。真实PG测试构造205本更相似但超预算的书，预算内目标仍可被召回。

适用当前小商品库。MySQL快照过滤与ID列表规模、现有全量读取仍有扩展成本；尚未证明大规模性能。读MySQL与调用PG/模型不持有跨系统长事务，最终复核避免把涨价/售罄商品继续推荐；真正库存预占仍由下单事务处理。

## 保留的安全与一致性处理

- 所有聊天入口仍经过原登录控制，工具不接收用户ID，不包含写操作。
- 明确书名未找到时不替换成相似书；模型失败返回暂不可用，不绕开价格或把未经选择的候选直接推荐。
- 选品期间书名/介绍/规格变化导致证据过期时跳过该商品；价格库存变化重新检查。
- 路由日志只记录工具、耗时、token等诊断；聊天控制器删除原话输出。模型密钥和供应商错误正文不写入测试文档。
