## 快速定位

| 面试官提问 | 首先讲清什么 | 去哪里复习 |
| --- | --- | --- |
| 你的项目最值得展开的点是什么？ | 从原有缺陷讲到可验证的交易正确性 | 01 |
| MySQL 和 Redis 库存怎样一致？ | 成交权威在 MySQL，展示缓存最终收敛 | 02：Q2、Q7 |
| 并发最后一件商品会怎样？ | 条件更新、影响行数、整个事务回滚 | 02：Q1、Q3 |
| 重复点击／网络重试会多下单吗？ | 同一请求键、参数摘要、数据库唯一约束 | 02：Q4 |
| 30 分钟未支付如何关闭？ | expires_at → Outbox → 延迟消息 → 查单关单 | 03：Q1 |
| 支付成功与超时同时发生？ | 渠道核对、订单行锁、重新检查状态 | 03：Q3 |
| 数据库成功但消息发送失败？ | 同事务保存 Outbox，后台可恢复投递 | 04：Q1 |
| Broker 收到但生产者没收到确认？ | 允许重发，eventId 不变，消费者幂等 | 04：Q2、Q3 |
| MQ 挂了还能下单吗？ | 下单不直接依赖 Broker；积压与补偿容量有边界 | 04：Q6 |
| 你如何测试 RAG 效果？ | 分层评测、固定标签、关键词基线与真实模型验收缺口 | 06：Q2–Q11 |
| 怎么证明可靠？ | 引用明确测试及断言，说明未测内容 | 01：Q3；测试方法与可信度 |

## 练习方式

先用 30–60 秒给出“业务风险 → 当前处理 → 失败恢复 → 验证结果”，再根据追问展开 SQL、锁和消息时序。不要一开始罗列所有中间件。

文中的“当前实现”可对照 [实现目录](../实现/README.md)；“后续优化”只能作为设计讨论。更新业务代码后，应同步修订对应回答。
