# RAG 与商品索引一致性

> 更新口径：已完成 [真实模型首次试验](../测试/2026-09-17-真实模型首次评测.md)：三策略各 50 题、生成 10 题。纯向量标注召回有改善但负例更多，混合检索尚无整体优势；生成 5 题呈现模型选品引用、4 题回退、1 题检索为空。以下未接入的表述属于此前基线，不能作为当前状态；首次试验也不代表完成独立质量验收。

## 1. 为什么商城同时用 MySQL 和 pgvector？

MySQL 是交易和商品事实来源；pgvector 保存商品介绍的派生向量，用于语义召回。Embedding 解决“用户表达与商品介绍用词不同”，数据库负责持久化与相似度查询。价格/库存实时读取 MySQL，避免向量更新延迟导致过期事实。

## 2. 商品修改成功，索引没更新怎么办？

商品修改与 Outbox 在同一 MySQL 事务。投递失败退避重试；broker 成功接收后仍要等消费者索引提交成功才ACK。最终重试耗尽可能进死信队列，需要告警、重放。周期核对覆盖消息丢失、恢复旧备份和直接导入未产生事件等情况。跨库是最终一致，没有宣称分布式事务。

## 3. 重复、乱序消费如何处理？

消息只携带商品ID，不携带要覆盖的新正文。消费者取得 PG 事务互斥锁后重新读最新 MySQL 状态，稳定 UUID 覆盖同一文档，内容hash相同跳过计算。Embedding过程中商品又变了，写后复读发现变化就回滚重试。协议version与商品版本不同；本实现用锁内最新读和内容校验，不能说实现了商品递增版本CAS。

## 4. 为什么不用自己保存 HashMap？

重启恢复、文件写入中断、备份、多个实例共享等机制都有成本。当前用 Spring AI PgVectorStore 复用成熟持久化存储，代价是新增 PostgreSQL 以及同步运维。默认精确搜索适合小数据；未来 HNSW 用额外内存和部分召回损失换速度，需要实测。

## 5. 模型换了，向量维度相同还能直接用吗？

不能。相同维度不代表同一个语义空间。索引配置绑定模型、维度、文本规则和源数据namespace；不匹配拒绝读写。新模型建立独立库、重建评测后切换。配置丢失且向量存在时也拒绝盲目接管。

## 6. 为什么混合检索？

书名等精确需求适合关键词，主题表达适合语义召回。不同分数不能直接加，RRF按排名融合。当前关键词是小目录字符串规则，不是BM25；当前没有reranker模型，不把价格/评分加分包装成语义重排。

## 7. 怎样防止模型乱报价格、商品和引用？

候选ID白名单、整型范围验证、证据必须是候选文档原文；价格与商品信息由后端读取。生成完再次校验上下架/库存/预算。阶段一已修复：合法空选品返回候选不匹配；模型异常提示推荐不可用，不回填未经相关性复核的候选。但证据存在并不等于推荐符合所有主观需求，仍需相关性评测。

## 8. 怎样证明这套东西有效？

分四层说明：纯检索规则/故障单元测试；真实MySQL事务回滚；真实PG重启实例/重复写/模型隔离/并发更新；真实MQ首次失败后的重投。固定测试向量只能证明链路正确，不能证明语义质量。100件合成商品、50条标注问题用来对比关键词和真实Embedding，现有质量结果仅为关键词基线，真实 Embedding 与生成层效果尚待验证。常见指标、数据效果与面试追问见 [RAG 效果评测](06-RAG效果评测与追问.md)。

## 9. 当前有什么取舍？

全局PG写锁降低实现复杂度但限制索引吞吐；关键词扫描全目录适用于小规模；固定阈值尚待真实模型评测；单实例环境未做高可用压测。模型调用放在独立索引任务/消费线程，不能占用订单超时扫描的公共定时线程。

详细代码、运行方式和实际结果：[实现说明](../实现/SpringAI与pgvector.md)、[验证记录](../测试/RAG验证记录.md)。

## 10. 为什么不能把模型空选品和模型失败统一降级？

空选品是一次合法业务判断，可能表示候选与需求不符；调用失败是技术故障，不能由此判断商品不存在。原先两者都回填候选，导致量子芯片问题被推荐 Redis。现在分别返回无匹配与暂不可用；正常选品仍做 ID、引用及实时事实校验。诊断只记 finish_reason、用量、模型与耗时，不存推理正文。真实 10 题复测仍有错误拒绝与选错书，不能把分支修复当作语义质量全部达标。见 [修复验证](../测试/2026-09-17-RAG阶段一修复验证.md)。

## 阶段二追问：为什么检索命中仍可能推荐失败？

检索召回、候选过滤、模型选择是三个边界。q32 已召回 79.99 元的书，但上下文没提供价格，模型无法核验预算而拒绝；现在传入实时价格事实。q35 暴露单一阈值和融合截断可能漏掉合适书，因此选品保留两路候选，再由模型筛选。不能用 Recall@5 代替最终回答正确率。

**为什么不一律提高相似度阈值？** dev 集无匹配题最高相似度约 0.532，而部分正确结果只有 0.523。提高到 0.54 会减少误召回，也损失相关结果；需要报告取舍。RRF 分数只是名次融合，不是相关概率。

**模型读懂“不要源码”了吗？** 本次仅支持结构化 excludedTopics 字面过滤。自然语言提取、历史补全和意图路由放在 Agent 层；服务端负责验证参数和执行过滤，不盲信模型。

**怎么证明有效？** 先用 dev 调阈值，再跑旧 heldout 与冻结新题；保存原始响应、预测、失败案例，并单独测生成。开发者编写的合成题有偏差，不能声称真实用户准确率。具体分数、成功与失败例子见[阶段二报告](../测试/2026-09-17-RAG阶段二修复验证.md)。
