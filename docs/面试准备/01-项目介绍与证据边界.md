# 项目介绍与证据边界

## Q1. 请介绍一下你的项目，以及你做过的关键改造

### 一分钟回答示例

> 我的项目是一个电商应用。这一轮主要完善普通交易链路：原先下单扣 Redis，但数据库没有同步预占，支付和超时又依赖可修改的购物车，失败时容易出现库存和订单不一致。我把订单、商品快照、MySQL 库存预占和 Outbox 放进同一个事务，下单加入 requestId 幂等，支付、取消、超时通过订单行锁控制状态转移。随后接入一条 RocketMQ 延迟消息链路处理订单超时，并用数据库扫描补偿消息异常和关单中的重试。我还验证了并发抢库存、重复回调、发送确认丢失和 Broker 强杀后的消息恢复。

这段话讲的是当前代码。若面试官问开发分工或工具使用，应如实说明自己的参与和理解程度；能够现场解释关键方法、修改假设并分析结果，比背叙述更重要。

### 常见追问

- 为什么没有一上来用 Redis 扣库存？见 [库存一致性 Q2](02-库存一致性与下单事务.md)。
- 最难的故障是什么？可展开“资金结果未知时不能直接释放库存”，或“发送成功但确认丢失”。
- 为什么只有一条 MQ 链路？先验证基础投递、幂等和恢复能力，再考虑索引等业务复用。

## Q2. 如何写简历而不夸大？

可以基于当前实现写：

- 重构订单交易链路，以 MySQL 条件更新实现库存预占，统一支付／取消／超时状态转移，加入订单快照与请求幂等。
- 基于 MySQL Outbox 与 RocketMQ 延迟消息实现超时检查，结合消费幂等、发送租约和数据库补偿扫描处理重复投递及故障恢复。
- 建立并发与故障测试，在独立 MySQL 验证 12 个并发买家争抢 5 件库存，实测 Broker 强杀重启后的延时消息恢复。

不能直接写成“支撑十万 QPS”“零丢失”“金融级”“生产多副本容灾”。当前没有这些证据。不要把单节点恢复试验描述成高可用集群验收。

## Q3. 你做过哪些测试，能证明什么？

| 已执行证据 | 能支持的结论 | 不能据此推导 |
| --- | --- | --- |
| 后端干净构建，默认 26 项测试通过 | 这些回归场景在测试环境通过，代码可打包 | 所有功能端到端可用 |
| MySQL 19 项事务测试通过 | 指定场景下实际 InnoDB 事务、锁、条件更新有效 | 完整生产容量和所有隔离级别都验证过 |
| 12 买家争抢 5 件，正好 5 单成功 | 此并发测试没有超卖，frozen=5 | 系统最大吞吐为某个数值 |
| 真实 Broker 确认后 SIGKILL，原存储重启 | 本地单节点已确认延时消息在该故障场景恢复 | 磁盘损坏、跨机灾备均无丢失 |
| 同事件重复消费 | 当前状态保护避免重复释放 | 所有未来消费者天然幂等 |
| 本地生成 RSA 签名校验商户字段 | 通知安全逻辑在本地测试中有效 | 支付宝沙箱网络和商户接入已验收 |

19 项 MySQL 测试是事务套件换真实数据库重跑，与默认 26 项有重叠；不能相加宣传为 45 个独立用例。详见 [原始输出摘要](../测试/订单验证记录.md)。

## Q4. 面试官问“现在还有什么问题”，怎么回答？

优先讲与核心链路直接相关的边界，并给出改进条件：

1. **支付结果未知的收敛**：当前保留库存、持续重试，第 10 次起记录异常；尤其“生成表单但用户没打开”的查无交易场景，仍可能需要人工核对。后续要完成沙箱验证、支付尝试记录、对账及受控退款流程。
2. **热点库存吞吐**：一件热门商品仍竞争同一库存行；当前正确性优先，后续依据压测决定限流、活动库存或分桶，不能直接声称消除了热点锁。
3. **运维能力**：已有日志、重试字段和巡检 SQL，尚无完整告警通知、异常处置界面、Outbox 清理及死信重放流程。
4. **部署边界**：现有库迁移尚未执行；库存语义改变前需要核对旧订单。Redis 真进程重启、生产多副本容灾未实测。

参考 [当前实现和限制](../实现/普通订单与超时消息.md)。

## Q5. 全栈或 AI 应用岗位如何衔接这个项目？

**当前可讲的全栈点**：前端防重点击和复用请求键，后端持久幂等；前端展示 CLOSING／已超时，后端再次校验权限和截止时间；商品页展示可售量，成交由数据库判断。

**AI 方向的后续设计**：如果导购 Agent 调用加购或下单工具，也必须调用这些受控业务服务，继承用户身份、幂等键、服务端计价与状态校验。不能让模型决定库存是否充足，或直接改订单状态。涉及交易写入时还需要确认机制和可追踪的工具调用记录。

这是可复用的业务基础，并不代表当前已经实现 Agent 自动下单、确认流程或完整工具审计。秒杀同样属于 [后续候选设计](../计划/后续候选-秒杀场景.md)。
